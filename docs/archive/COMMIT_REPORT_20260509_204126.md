## Detailed Changes

- **speaking_foundation.sql**: creates `speaking_prompts` (linked to word_senses), `speaking_events`; status CHECK constraint; unique indexes for idempotency
- **word_store.js / postgres_word_store.js**: full CRUD for speaking prompts and events; vocabulary JOIN returns approved prompt; `buildSpeakingSummary` aggregates weekly stats; `localAudioPath` stripped from all payloads
- **app.js**: `GET /v1/speaking/summary`, `GET/POST /v1/admin/speaking-prompts`, `PATCH /v1/admin/speaking-prompts/:id`
- **ISpeakingAudioService**: abstraction over flutter_tts + record + just_audio — UI never depends on plugin APIs
- **SpeakingRepository**: orchestrates permission check, record/stop, ObjectBox persistence, sync queue (speaking events stripped of localAudioPath), first-recording analytics event, deleteAll
- **SpeakingDrillScreen**: 3-minute drill (up to 5 most-recently-cached prompts), per-prompt record/rate flow, summary screen, empty state
- **LearningDrawer**: speaking stats bottom sheet (weekly summary from backend) + delete-all recordings with confirmation dialog; gated by speakingRepository != null
- **Drill selection tests**: fixed ObjectBox cross-test data leakage by using unique databaseName per test (_drillTestCounter)

## Affected Flows

- **Card loading**: vocabulary cards now carry optional SpeakingPrompt when backend has an approved prompt for that word sense
- **Speaking card UX**: expandable panel on vocabulary card; listen/record/retry/rate; privacy note
- **3-minute drill**: entry from drawer; selects up to 5 cached prompts; summary on completion
- **Study-event sync**: `POST /v1/study-events/sync` now accepts mixed rating/speaking batches
